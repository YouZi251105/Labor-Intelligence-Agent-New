版本：1.0  
更新日期：2026-11-02
Base URL：`http://127.0.0.1:8000/api/v1`

机器可读文件：`docs/api/openapi.v1.json`

## 1. 契约状态

本文档同时包含：

- 当前已实现接口。
- 阶段 1 工作流接口，已实现并完成前后端联调。

后端 Pydantic Schema 是实现的权威来源。前端类型、Mock 和测试必须与本文档及 OpenAPI 一致。

## 2. 通用规则

### 认证

除注册、登录和健康检查外，请求必须包含：

```http
Authorization: Bearer <access_token>
```

### 内容类型

JSON 请求：

```http
Content-Type: application/json
```

文件上传：

```http
Content-Type: multipart/form-data
```

### 错误

统一结构：

```json
{
  "detail": "错误说明"
}
```

状态码：

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 参数、文件或状态不允许 |
| 401 | 未登录或 Token 失效 |
| 403 | 角色无权 |
| 404 | 资源不存在或无权访问 |
| 409 | 用户名或材料重复 |
| 422 | 请求 Schema 校验失败 |
| 500 | 服务端错误 |

### 时间

所有时间字段使用 ISO 8601：

```text
2026-11-01T08:45:51.839044
```

### ID

当前使用整数 ID。前端不得自行推导资源关系。

### dispute_type

两级法定口径：劳动争议（`group: labor`，6 类）与劳务纠纷（`group: service`，4 类）。分类名称以法律内容负责人提供的口径为准。

```text
labor_confirmation   确认劳动关系争议
labor_contract       劳动合同订立、履行、变更、解除、终止争议
labor_termination    除名、辞退、辞职、自动离职争议
labor_benefits       工作时间、休息休假、社会保险、福利、培训、劳动保护争议
labor_pay            劳动报酬、加班费、工伤医疗费、经济补偿、赔偿金争议
labor_other          其他法定劳动争议
service_pay          劳务费拖欠纠纷
service_quality      劳务成果、质量纠纷
service_injury       提供劳务致人、自身损害赔偿纠纷
service_breach       劳务合同解除、违约责任、违约金纠纷
```

`GET /meta/dictionary` 的 disputes 项含 `group` 字段（`labor` / `service`），前端下拉按组展示。历史案件中的旧枚举值（wage、general 等）已在数据库迁移中自动映射为新值。

### GET /cases

权限：已登录

返回当前角色可访问案件：

- 劳动者：自己的案件。
- 律师：分配给自己的案件。
- 管理员：全部案件。

查询参数（均可选）：

- `status`：`active`（默认，未归档）、`archived`、`all`。
- `dispute_type`：按纠纷类型精确过滤。
- `q`：按标题、摘要、事实模糊搜索。

响应：`CaseRead[]`

权限：案件所有者本人，且角色必须为 `user`。

请求：

权限：案件所有者本人，且角色必须为 `user`。

### POST /cases/{case_id}/evidence

权限：案件所有者本人，且角色必须为 `user`。

请求：

```text
multipart/form-data
file=<binary>
```

限制：

- 单文件不超过 20MB。
- 支持 jpg、jpeg、png、webp、pdf、txt、doc、docx。
- 文件内容与扩展名必须匹配。
- 同一案件不能上传相同 SHA256 文件。
- JPG、JPEG、PNG、WebP 上传前会执行图片真实性初筛，包括元数据编辑软件痕迹、重压缩异常、拼接边界和规则涂抹痕迹。初筛不构成真伪鉴定。

响应 `201`：`EvidenceRead`

图片初筛通过时，`assessment.forensics` 增量返回：

```json
{
  "image_type": "screenshot",
  "suspicious": false,
  "reasons": ["未发现明显伪造痕迹"],
  "checks": {
    "exif": true,
    "splice": true,
    "mosaic": true
  },
  "disclaimer": "系统初步筛查仅供参考，不构成真伪鉴定结论。"
}
```

初筛发现明显异常时返回 `422`，文件不会进入对象存储和证据表：

```json
{
  "detail": "图片真实性初筛未通过：检测到规则色块网格，疑似马赛克或涂抹痕迹。系统初步筛查仅供参考，不构成真伪鉴定结论。请上传未经拼接或涂抹的原始图片；如确有合理脱敏需要，请通过人工协助提交。"
}
```

### POST /cases/{case_id}/transitions

权限：案件所有者本人，且角色必须为 `user`。

请求优先使用 `option_id`：

```json
{
  "option_id": "evidence-to-procedure",
  "note": "用户确认进入协商"
}
```

旧调用仍可使用：

```json
{
  "target_stage": "procedure",
  "note": "兼容旧客户端的阶段请求"
}
```

规则：

- `option_id` 必须存在于当前节点返回的 `options` 中；同时传入时优先使用 `option_id`。
- 只允许服务端规则计算为 `enabled=true` 的选项。
- 条件不满足返回 `400`。
- AI 只能建议，不能直接调用状态转换。
- 成功响应返回最新 workflow。
- 非法跳转或前置条件未满足返回 `400`。
- 选择结果写入 `Case.classification.workflow_choices`，记录规则包版本、来源节点、目标节点、时间和备注。

## 15. 律师服务（预约/对话/复核）

状态：MVP，实现被动介入（用户预约）与主动介入（结案复核）。

### 预约状态机

```text
pending → accepted（律师受理，自动创建会话）
pending → rejected（律师拒绝）
pending/accepted → cancelled（仅预约所属用户或管理员取消）
accepted → in_session（首次消息发送，会话进入咨询中）
in_session → completed（对话结束，会话关闭）
```

同一案件同时最多一个 `pending`/`accepted`/`in_session` 预约。

### 接口

- `POST /lawyer-service/requests`（`user`）：创建预约，`{case_id, reason, preferred_date?, preferred_slot?, preferred_time?, priority}`。
  - `preferred_date`：`YYYY-MM-DD`，必须在今天起 7 天内，否则返回 400。
  - `preferred_slot`：`morning | afternoon | evening`，分别对应上午 09:00-12:00、下午 14:00-18:00、晚间 18:00-21:00。
  - 同时提供日期和时段时，后端自动生成展示文本 `preferred_time`（如 `11月6日 晚间 18:00-21:00`），客户端传的自由文本仅作兜底。
- `GET /lawyer-service/requests`：用户看自己的、律师看待受理或分配给自己的。响应含 `preferred_date`、`preferred_slot`、`reject_reason`。
- `PATCH /lawyer-service/requests/{id}`（`lawyer`）：`{accept: bool, reject_reason?}` 受理或拒绝；拒绝时 `reject_reason` 必填（缺失返回 422），理由会展示给用户；受理时自动创建会话。受理遵循「谁受理谁负责」：案件尚无承办律师时由受理律师接手；案件已被管理员分配给其他律师时返回 409，不允许受理。
- `POST /lawyer-service/requests/{id}/cancel`：仅预约所属用户或管理员可取消；已受理的预约取消时同步关闭关联会话。律师应使用拒绝接口说明无法受理的原因，不能取消其他用户的预约。
- `GET /lawyer-service/sessions` / `POST /lawyer-service/sessions/{id}/messages` / `GET .../messages`：会话与消息（仅当事人双方可访问，消息只增不改）。消息响应含附件元数据 `attachment_name`、`attachment_size`、`attachment_type`。
- `POST /lawyer-service/sessions/{id}/messages/file`：`multipart/form-data`（`content` 可选 + `file`）。附件支持 jpg、jpeg、png、webp、pdf、txt、doc、docx，不超过 10MB，内容与扩展名必须匹配；`content` 与附件至少一项存在。响应 `201`：`ConsultationMessageRead`（含附件元数据）。
- `GET /lawyer-service/sessions/{id}/messages/{message_id}/attachment`：下载消息附件，仅会话当事人可访问；附件以 `Content-Disposition: attachment` 返回。
- `POST /lawyer-service/sessions/{id}/close`：结束会话。
- `POST /lawyer-service/cases/{case_id}/review`（`user`）：结案前生成复核任务。
- `GET /lawyer-service/cases/{case_id}/review`：查看复核结果。
- `GET /lawyer-service/todos`（`lawyer`）：待受理预约 + 待复核任务；待受理预约按「加急优先，再按 `preferred_date`、时段（上午→下午→晚间）、提交时间」升序排序，未选日期的排最后。响应含 `cases` 字段（键为案件 ID 字符串，值为 `{id, title, dispute_type, stage}`），用于前端展示案件标题。
- `POST /lawyer-service/reviews/{review_id}/decision`（案件所有者本人，角色 `user`）：复核结论出来后用户选择后续方式，`{decision: self_handle | lawyer_assist}`，可重复调用变更选择；复核未完成时返回 409。响应含 `user_decision`、`user_decision_at`。

预约受理时效（前端展示承诺，暂不做强制升级）：加急 2 小时内受理、普通 24 小时内受理；受理后律师按用户所选时段开始回复。

关键操作（预约创建/受理/拒绝/取消、会话关闭、复核提交）均写入审计日志。

- `GET /lawyer-service/reviews/{review_id}/case-brief`（`lawyer`）：复核案件简报，供律师复核时查看材料。返回 `{case: CaseRead, evidence: {items, assessment}, documents: DocumentRead[]}`。待分配（`lawyer_id` 为空）的复核任务对所有律师开放；已分配的仅限承办律师，其余返回 404。
- `POST /lawyer-service/reviews/{review_id}/submit`（`lawyer`）：提交复核结论 `{conclusion, comment}`；仅 `pending` 状态可提交。案件已由其他律师承办时返回 409；案件未分配或由当前律师承办时，提交后复核任务与案件分配给该律师。

## 15A. 管理端字典管理

状态：MVP。字典包为版本化内容（复用规则包模式），状态机 `draft → published → retired`。

`draft` 可修改可删除；`published` 不可变不可删除；发布新版本时旧 `published` 自动置为 `retired`。发布后 `GET /meta/dictionary`、AI 分类、证据规则评估和文书生成立即读取新口径（进程内缓存即时失效），并写入审计日志。无任何已发布包时回落到内置默认口径。包内容必须保留 `labor_other` 作为兜底分类。

### DictionaryPackageContent

```json
{
  "disputes": [
    {
      "value": "labor_pay",
      "label": "劳动报酬、加班费、工伤医疗费、经济补偿、赔偿金争议",
      "group": "labor",
      "keywords": ["工资", "欠薪"],
      "required_categories": ["payroll", "chat", "contract"],
      "core_categories": ["payroll", "chat"],
      "claim_text": "请求裁决被申请人支付拖欠的劳动报酬。"
    }
  ],
  "stages": [{ "value": "intake", "label": "识别问题", "description": "…" }],
  "evidence_categories": [{ "value": "payroll", "label": "工资或转账记录", "keywords": [] }],
  "migrations": { "wage": "labor_pay" }
}
```

校验规则（违反返回 422，`detail.errors` 为错误列表）：

- `value` 只能使用小写字母、数字和下划线，且包内唯一。
- `group` 只能是 `labor` 或 `service`。
- `core_categories` 必须是 `required_categories` 的子集，且引用的类别必须存在于 `evidence_categories`。
- 必须保留 `labor_other`。
- `migrations` 的目标值必须是包内有效纠纷标识。

### 接口

- `GET /admin/dictionary/versions`（`admin`）：版本列表（按版本号倒序），`DictionaryVersionSummary[]`。
- `GET /admin/dictionary/active`（`admin`）：当前生效口径，`{source: published | default, version, content}`，供编辑器初始化。
- `GET /admin/dictionary/versions/{id}`（`admin`）：版本详情（含 `content`）。
- `POST /admin/dictionary/versions`（`admin`）：创建草稿，`{content}`；版本号自动取最大值 +1。`201`。
- `PUT /admin/dictionary/versions/{id}`（`admin`）：修改草稿，`{content}`；非 `draft` 返回 409。
- `POST /admin/dictionary/versions/{id}/publish`（`admin`）：发布；仅 `draft` 可发布（否则 409），旧 `published` 置为 `retired`。
- `DELETE /admin/dictionary/versions/{id}`（`admin`）：删除；仅 `draft` 可删除（否则 409）。`204`。

`GET /meta/dictionary` 的行为自本节起变为：返回最新 `published` 包的展示字段（无包时返回内置默认），响应结构不变。
