## 2. 通用规则

### 认证

除注册、登录和健康检查外，请求必须包含：

```http
Authorization: Bearer <access_token>
```

### 内容类型

JSON 请求：

```http
Content-Type: application/json
```

文件上传：

```http
Content-Type: multipart/form-data
```

### 错误

统一结构：

```json
{
  "detail": "错误说明"
}
```

状态码：

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 参数、文件或状态不允许 |
| 401 | 未登录或 Token 失效 |
| 403 | 角色无权 |
| 404 | 资源不存在或无权访问 |
| 409 | 用户名或材料重复 |
| 422 | 请求 Schema 校验失败 |
| 500 | 服务端错误 |

### 时间

所有时间字段使用 ISO 8601：

```text
2026-11-01T08:45:51.839044
```

### ID

当前使用整数 ID。前端不得自行推导资源关系。

### POST /cases/{case_id}/transitions

权限：案件所有者、分配律师或管理员。

请求：

```json
{
  "target_stage": "procedure",
  "note": "用户确认进入协商"
}
```

规则：

- 只允许服务端批准的相邻转换或符合规则的跳转。
- 条件不满足返回 `400`。
- AI 只能建议，不能直接调用状态转换。
- 成功响应返回最新 workflow。
- 当前只允许工作流返回的 `options` 中 `enabled=true` 的下一阶段。
- 非法跳转或前置条件未满足返回 `400`。

## 13. 阶段 2 证据与文书增强接口

状态：契约已冻结，前后端联调完成，阶段 2 验收通过。

### 证据提取字段

`EvidenceRead` 增量增加：

```json
{
  "text_preview": "9月工资5000元，10月工资5000元，尚未支付。",
  "extraction_status": "extracted",
  "extraction_message": "已提取 26 个字符。"
}
```

`extraction_status`：

```text
extracted
ocr_required
unsupported
failed
```

既有字段含义不变。上传接口仍返回 `201`，上传成功后自动执行一次文本提取。

### GET /cases/{case_id}/evidence-assessment

权限：案件所有者、分配律师或管理员。

用途：返回证据「四性」评估（合法性、关联性、充分性、完整性），用于材料整理提示，不下真伪鉴定结论。

响应：

```json
{
  "case_id": 1,
  "dispute_type": "wage",
  "legality": {
    "status": "ok",
    "findings": [
      { "level": "issue", "message": "某材料已被隔离，需人工复核。" }
    ]
  },
  "relevance": {
    "status": "warning",
    "findings": [
      { "level": "warning", "message": "某材料与案件关联性需要人工确认。" }
    ]
  },
  "sufficiency": {
    "status": "issue",
    "findings": [
      { "level": "issue", "message": "缺少核心证据：工资或转账记录、聊天记录。" }
    ]
  },
  "completeness": {
    "status": "needs_more",
    "required_categories": ["payroll", "chat", "contract"],
    "present_categories": [],
    "missing_categories": ["payroll", "chat", "contract"],
    "missing_labels": ["工资或转账记录", "聊天记录", "合同或协议"]
  },
  "disclaimer": "规则评估仅用于材料整理提示，不构成证据合法性或证明力结论。"
}
```

`status` 取值：

- `legality`、`sufficiency`：`ok` / `issue`
- `relevance`：`ok` / `warning`
- `completeness`：`ready` / `needs_more`

`findings[].level`：`warning` / `issue`。

评估为本地演示规则，正式法律依据由法律内容负责人复核后补充。

### POST /cases/{case_id}/evidence/{evidence_id}/extract

权限：案件所有者、分配律师或管理员。

用途：重新提取材料文本。适用于 OCR 引擎恢复、文件替换或首次提取失败。

响应：

```json
{
  "evidence_id": 12,
  "extraction_status": "extracted",
  "extracted_text": "材料识别后的文本",
  "message": "已提取 9 个字符。"
}
```

失败不会删除原文件：

- OCR 引擎不可用时返回 `200`，状态为 `ocr_required`。
- 文件损坏时返回 `200`，状态为 `failed`。
- 旧版 `.doc` 文件返回 `200`，状态为 `unsupported`。

### GET /cases/{case_id}/evidence/{evidence_id}/download

权限：案件所有者、分配律师或管理员。

响应：原始文件字节流。成功访问写入 `evidence.downloaded` 审计事件，不记录文件正文。

### POST /cases/{case_id}/contract-review/file

权限：案件所有者、分配律师或管理员。

请求类型：`multipart/form-data`。

字段：`file`。

支持：TXT、PDF、DOCX、JPG、JPEG、PNG、WEBP，单文件最大 20MB。

成功响应：

```json
{
  "filename": "劳动合同.docx",
  "extraction_status": "extracted",
  "extracted_text": "合同正文",
  "review": {
    "risk_level": "high",
    "findings": [
      {
        "level": "high",
        "title": "放弃社会保险条款",
        "detail": "该条款可能影响劳动者社会保险权益，应重点人工核验。"
      }
    ],
    "missing_items": ["工作时间和休息休假"],
    "disclaimer": "本结果仅基于文本进行规则提示，不构成合同真实性或法律效力结论。"
  }
}
```

错误：

- 文件类型或大小不合规返回 `400`。
- OCR 不可用、文件损坏或没有可提取文本返回 `422`。

### POST /cases/{case_id}/documents/{document_id}/revisions

权限：案件所有者、分配律师或管理员。

请求：

```json
{
  "title": "劳动仲裁申请书",
  "content": "用户编辑后的文书内容",
  "status": "draft"
}
```

规则：

- 不覆盖原版本。
- 新版本号在原文书基础上递增。
- 沿用原文书的证据快照。
- `status` 只允许 `draft`。

响应：新的 `DocumentRead`。

### GET /cases/{case_id}/documents/{document_id}/export

权限：案件所有者、分配律师或管理员。

响应类型：

```text

application/pdf
```

响应头包含附件文件名。TXT 下载接口保留。
