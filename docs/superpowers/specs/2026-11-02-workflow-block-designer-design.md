# 受约束流程积木与可视化设计器设计

## 目标

在现有版本化规则包之上增加受约束的可视化流程设计器，让内容人员通过固定积木、固定条件类型和固定连接规则组合案件流程，而不是直接编写任意代码或表达式。

## 积木类型

- `stage`：单一顺序出口。
- `decision`：至少两个人工选择出口。
- `evidence_gate`：证据满足与不满足两个出口。
- `lawyer_gate`：律师已分配与未分配两个出口。
- `end`：流程终点，不能有出口。

所有积木仍编译成现有 `WorkflowRulePackage.nodes` 和 `options`，运行时不执行管理端生成的代码。

## Designer 元数据

规则包增加可选 `designer`：

```json
{
  "designer": {
    "version": 1,
    "blocks": [
      {
        "id": "intake",
        "block_type": "decision",
        "position": {"x": 25, "y": 35}
      }
    ]
  }
}
```

`designer.blocks` 必须与 `nodes` 一一对应。坐标只用于可视化，不参与业务判断。

## 校验

- 起点不能是结束块。
- 结束块不能有出口。
- 非结束块必须有出口。
- 阶段块和选择块只能使用 `always` 条件。
- 选择块至少有两个出口。
- 证据条件块必须包含 `evidence_ready` 和兜底出口。
- 律师条件块必须包含 `lawyer_assigned` 和兜底出口。
- 目标阶段必须与目标节点所属阶段一致。
- 所有节点必须从起点可达。

## 运行时

节点 ID 与业务阶段解耦。当前节点保存在 `Case.classification.workflow_node_id`，业务阶段仍保存在 `Case.stage`。决策记录同时保存来源节点和目标节点。

## 管理端交互

- 左侧积木面板只提供平台批准的块类型。
- 中间画布支持拖入积木和拖动位置。
- 右侧属性面板编辑名称、阶段、目标和结果文案。
- 连接目标只能从已有节点中选择，不能输入任意跳转。
- 可视化模式与 JSON 模式双向同步。
- 已发布、待复核和已批准版本只读。

## 后续

Excel 转换和 AI 生成流程草稿后续都生成同一套积木/规则包结构，并复用现有校验、审核和发布流程。
