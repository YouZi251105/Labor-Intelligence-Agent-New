# 咨询流式输出与可选参考资料设计

## 目标

将 AI 咨询从“等待完整 JSON 后一次性显示”改为渐进式输出：

- 服务端读取千问模型的真实 token 流。
- 首段内容到达后立即显示，不再等待整段回答完成。
- 等待期间显示“正在理解问题”“正在生成回复”等阶段状态。
- 流式 Markdown 始终经过解析和安全清理。
- 如果存在已核验的法条或类案，回答结束后默认折叠展示；没有则不显示。
- 保留现有普通咨询接口，失败时可以回退。

## 接口

新增：

`POST /api/v1/cases/{case_id}/consultations/stream`

请求体与现有咨询接口一致：

```json
{"message": "用户问题"}
```

响应使用 `text/event-stream`，事件依次为：

- `status`：阶段状态，包含 `thinking`、`generating`。
- `delta`：正文增量，包含 `text`。
- `references`：可选参考资料；无内容时不发送。
- `done`：已完成消息、结构化结果和案件状态。
- `error`：生成失败，包含可展示错误信息。

普通接口 `/consultations` 保持兼容，不作为前端默认路径。

## 服务端

### 千问流

- 使用 `httpx.AsyncClient.stream()` 调用千问兼容接口。
- 从 `choices[0].delta.content` 读取正文 token。
- 忽略模型内部推理内容，只把最终回答曝露给用户。
- 首 token 前发送 `thinking`，首 token 后发送一次 `generating`。
- 千问不可用或没有正文时，生成本地规则回答并继续用同一 SSE 协议分段输出。
- 只持久化最终完整回答和结构化元数据；用户消息在开始生成前保存。

### 参考资料

新增结构化 `references` 字段，兼容现有字符串 `citations`：

- 法条：标题、条款摘要、来源名称、官方 URL、复核状态。
- 类案：案件名称、案号、法院、年份、裁判要旨、来源 URL。

只有通过来源核验和专业复核的内容才能进入 `references`。当前没有正式检索结果时返回空数组，前端不显示参考区。

## 前端

- 使用 `fetch + ReadableStream` 消费 SSE，不使用 `EventSource`，以支持 POST、JWT 和 JSON 请求体。
- 发送后立即推入用户消息，并创建一个临时 assistant 消息。
- 临时消息根据 `status` 事件显示阶段文案，收到 `delta` 后逐段追加正文。
- `done` 后用服务端正式消息替换临时消息。
- 连接中断时保留已生成内容，标记“生成中断”，允许用户重试。
- 发送期间只锁定当前发送按钮和追问按钮，不阻塞历史消息滚动。
- 仅当用户接近底部时自动滚到底部，避免打断向上阅读。

## Markdown

- 所有流式内容继续使用 `SafeMarkdown`。
- 流式态使用 `streaming` 属性：
  - 自动补齐末尾未闭合的代码围栏。
  - 对未闭合的粗体、引用和列表提供稳定渲染。
  - 继续使用 `DOMPurify`，禁止脚本、事件属性和危险链接。
  - 链接继续添加 `target="_blank"` 和 `rel="noopener noreferrer"`。
- Markdown 更新按浏览器动画帧节流，避免每个 token 都触发完整解析。

## 参考资料组件

- 新增 `ReferenceMaterials.vue`。
- 数量为 0 时不渲染。
- 有内容时使用原生 `<details>`，默认折叠。
- 标题显示“参考资料（N）”。
- 法条和类案分组展示，来源 URL 使用安全外链。
- 未核验内容不能进入组件。

## 测试

- 后端：
  - SSE 事件顺序和最终 `done`。
  - 千问流式 token 正常传递。
  - 千问异常时本地回退。
  - 用户消息、assistant 消息和结构化元数据正确持久化。
- 前端：
  - SSE 分帧与跨 chunk 解析。
  - 阶段文案更新。
  - 流式 Markdown 可安全渲染未闭合内容。
  - 没有参考资料时不渲染，有资料时默认折叠。
- Playwright：
  - 发起咨询后先出现等待状态，随后正文逐步增长。
  - 最终保留完整回答、追问选项和可选参考资料。
