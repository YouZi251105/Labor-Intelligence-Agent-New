# 规则包 Excel 中间层设计

## 目标

为不熟悉 JSON 的法律内容人员提供可下载、可回传的 Excel 工作簿。Excel 负责人工录入和审阅，后端负责将其转换为现有 `WorkflowRulePackage`，并继续复用当前的校验、版本审核、发布和运行时加载流程。

JSON 仍是唯一机器格式。数据库结构、规则引擎和现有可视化设计器不做替换。

## 非目标

- 不把 Word 作为规则导入来源。Word 中的自由文本、合并单元格和表格结构无法稳定表达节点引用与条件关系。
- 不在本阶段实现 Word 复核稿、Excel 在线编辑或 AI 自动生成规则。
- 不允许 Excel 中出现任意脚本、宏、公式或未登记字段。
- 不改变规则包状态机：`draft -> pending_review -> approved -> published -> retired`。

## 工作簿契约

下载的 `.xlsx` 固定包含以下工作表：

| 工作表 | 用途 | 关键列 |
| --- | --- | --- |
| 填写说明 | 颜色、字段、示例和校验说明 | 仅说明 |
| 基础信息 | 包标识、版本、地区、起点和免责声明 | 字段、值 |
| 阶段 | 案件流程阶段 | 阶段ID、显示名称、说明 |
| 节点 | 节点所属阶段与可选积木信息 | 节点ID、所属阶段、节点名称、积木类型、横坐标、纵坐标 |
| 路径 | 每个选项及其目标节点 | 路径ID、来源节点ID、顺序、选项名称、选项说明、目标节点ID、目标阶段、结果说明、下一步 |
| 前置条件 | 路径所需的 `always`、`evidence_ready`、`lawyer_assigned` 条件 | 路径ID、条件类型、提示文案 |
| 期限规则 | 路径关联的待复核期限 | 路径ID、期限ID、标题、说明、法律依据、起算事件、计算方式、复核状态 |
| 数据字典 | 积木类型、条件类型、期限计算方式和审核状态 | 隐藏工作表 |

要求：

- 表头文字和列顺序固定，列名不得由用户修改。
- 使用可读的中文表头，内部映射回现有英文 JSON 字段。
- 每个工作表第一行是表头，第二行开始是数据；说明页提供一条真实示例，不把示例混入数据页。
- 下拉字段使用数据验证。输入区域使用浅色背景，锁定说明和表头。
- 路径、节点、阶段 ID 只允许字母、数字、下划线、点和短横线。
- 节点无积木信息时省略 `designer`；只要任意节点填写积木字段，则所有节点必须完整填写积木字段。
- 路径按“顺序”列排序；顺序必须是正整数且同一来源节点内不重复。
- 空行忽略。完全空白的可选工作表不应导致导入失败。

## 转换规则

### Excel 到 JSON

1. 读取“基础信息”生成顶层字段。
2. 读取“阶段”“节点”“路径”“前置条件”“期限规则”生成对应数组和字典。
3. 使用路径ID将条件和期限挂回选项。
4. 生成 `WorkflowRulePackage`，交给现有 Pydantic 校验器。
5. 任一结构或引用错误都返回全部可收集错误，并包含工作表与 Excel 行号。

错误示例：

```text
路径!F5：目标节点 evidence 不存在
路径!C8：节点 intake 下的顺序 2 重复
前置条件!B9：条件类型 approval 不在允许范围内
```

导入成功后创建新的 `draft` 版本，并写入现有审计日志。重复的 `package_id + version` 仍返回 `409`。

### JSON 到 Excel

- 模板导出使用当前内置规则包。
- 当前版本导出使用所选规则包内容。
- 转换必须保持语义等价。再次导入导出的工作簿，应得到通过校验且业务内容一致的规则包。

## 接口设计

所有接口仅允许管理员访问。

### `GET /api/v1/admin/rule-packages/template.xlsx`

返回可填写的 `.xlsx` 模板，文件名包含模板版本和当前日期。

### `GET /api/v1/admin/rule-packages/{id}/export.xlsx`

将指定规则包导出为 Excel。已发布版本也可导出，用于复核和留档。

### `POST /api/v1/admin/rule-packages/import-excel`

- 请求类型：`multipart/form-data`
- 文件字段：`file`
- 仅接受 `.xlsx`，单文件上限 5 MiB。
- 成功：`201`，返回现有 `RulePackageDetail` 草稿。
- 字段或引用错误：`422`，响应包含结构化错误列表。
- 文件类型、大小或工作簿结构错误：`400`。
- 无管理员权限：`403`。

现有 JSON 模板、JSON 导入、在线校验、可视化编辑和审核发布接口全部保留。

## 管理端交互

规则包中心工具栏增加：

- `下载 Excel 模板`
- `导出当前 Excel`
- `导入 Excel`

保留原有 `下载 JSON 模板`、`导入 JSON`，并明确标注为高级格式。

Excel 导入成功后刷新版本列表并选中新草稿。失败时在页面显示按工作表和行号排序的错误列表，不能只显示“导入失败”。

## 安全与稳定性

- 使用 `openpyxl` 以只读模式加载工作簿，不执行宏、公式或外部链接。
- 拒绝 `.xlsm`、`.xls` 和伪造扩展名文件。
- 拒绝含公式的输入单元格，避免依赖缓存值或外部引用。
- 限制文件大小、工作表数量和有效数据行数，防止压缩炸弹和超大表格拖垮服务。
- 所有单元格按文本读取并按现有 Pydantic 长度限制截断校验，不直接信任 Excel 数据类型。
- 导入事务与 JSON 导入保持一致：校验成功后才写入数据库。

## 测试

后端至少覆盖：

1. 模板下载返回合法 `.xlsx` 和固定工作表。
2. 模板原样导入后通过校验，阶段、节点、路径、条件和期限数量与内置规则一致。
3. 导出后重新导入，核心内容语义一致。
4. 未知目标节点、重复顺序、非法条件和缺失必填字段返回带工作表及行号的错误。
5. 错误文件、超大文件、公式单元格和非管理员调用被拒绝。
6. 导入成功后进入 `draft`，可继续送审、批准和发布。

前端至少覆盖：

1. 三个 Excel 操作按钮可用，文件名和下载内容正确。
2. 上传成功刷新列表并显示新草稿。
3. 上传失败显示结构化错误和行号。
4. 1366×768、1920×1080 和移动端工具栏不溢出。
