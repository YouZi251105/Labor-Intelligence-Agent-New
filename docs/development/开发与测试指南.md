# 开发与测试指南

适用对象：前端、后端、测试和部署人员  
版本：0.2.0 Demo

## 1. 技术栈

### 前端

- Vue 3
- TypeScript
- Vite
- Pinia
- Vue Router
- Element Plus
- Lucide Vue
- Vitest
- Playwright

### 后端

- Python 3.13
- FastAPI
- Pydantic v2
- SQLAlchemy 2
- Argon2
- JWT
- SQLite/aiosqlite 本地演示
- PostgreSQL/asyncpg 生产配置
- Celery、Redis、MinIO 基础设施配置

## 3. 启动

### 一键启动

根目录双击：

```text
start.bat
```

### 后端手动启动

```powershell
cd backend
.\.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

### 前端手动启动

```powershell
cd frontend
npm run dev
```

## 4. 本地数据库

默认配置：

```text
sqlite+aiosqlite:///./data/demo.db
```

首次启动会自动：

1. 创建数据库表。
2. 创建演示用户。
3. 创建律师档案。
4. 创建一个欠薪演示案件。

演示数据位于：

```text
backend/data/demo.db
backend/data/uploads/
```

这些目录已在 `.gitignore` 中排除。

### 重置演示数据库

先停止后端，再删除演示数据库和上传材料：

```powershell
Remove-Item backend\data\demo.db -Force
Remove-Item backend\data\uploads -Recurse -Force
```

重新启动后端后会生成初始演示数据。

不要在已有正式数据的环境中执行。

## 5. 环境变量

后端参考：

```text
backend/.env.example
```

依赖声明：

- 主文件：`backend/pyproject.toml`
- 运行依赖兼容文件：`backend/requirements.txt`
- 开发依赖兼容文件：`backend/requirements-dev.txt`
- 根目录同名文件可作为 IDE 或部署工具的入口

推荐安装：

```powershell
cd backend
.\.venv\Scripts\python -m pip install -e ".[dev,quality]"
```

只识别 requirements 的工具：

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
```

常用配置：

| 变量 | 说明 |
|---|---|
| `APP_ENV` | development、test、production |
| `APP_DEBUG` | 调试开关 |
| `SECRET_KEY` | JWT 密钥 |
| `DATABASE_URL` | 数据库连接 |
| `DEMO_SEED` | 是否初始化演示数据 |
| `QIANWEN_API_KEY` | 千问 API Key |
| `QIANWEN_MODEL` | 默认 `qwen-plus` |
| `REDIS_URL` | Celery/Redis |
| `MINIO_*` | 对象存储 |
| `STORAGE_BACKEND` | `local` 或 `s3` |
| `TASK_BACKEND` | `inline` 或 `celery` |
| `TRUSTED_HOSTS` | 允许访问的 Host 列表 |
| `RATE_LIMIT_PER_MINUTE` | 登录和注册接口限流 |
| `ENABLE_METRICS` | 是否开放 `/metrics` |

前端：

```text
VITE_API_BASE_URL=/api/v1
```

不要提交真实 `.env` 或 API Key。

## 7. AI 配置

本地不配置 Key 时，系统使用规则演示。

配置真实模型：

本地配置文件：

```text
backend/.env
```

填写：

```env
QIANWEN_API_KEY=你的千问API Key
QIANWEN_MODEL=qwen-plus
```

如果项目根 `.env` 也存在，它会在后端 `.env` 之后加载，应避免在两处写不同配置。

AI 调用位于：

```text
backend/app/services/ai.py
```

如果模型请求失败，系统自动使用本地演示回复。

## 8. API 文档

后端启动后访问：

<http://127.0.0.1:8000/docs>

接口统一前缀：

```text
/api/v1
```

生成静态 OpenAPI 契约：

```powershell
cd backend
.\.venv\Scripts\python scripts\export_openapi.py
```

输出：

```text
docs/api/openapi.v1.json
```

接口行为变更时必须同步：

```text
docs/api/接口契约_v1.md
docs/api/openapi.v1.json
frontend/src/types/api.ts
```

新增接口时应同步：

- Pydantic schema
- 对象级权限
- 测试
- API 概览文档

### 规则包 Excel 回归

后端规则包 Excel 转换位于：

```text
backend/app/services/rule_package_excel.py
```

运行专项测试：

```powershell
cd backend
.\.venv\Scripts\python -m pytest tests\test_rule_package_excel.py tests\test_rule_package_admin.py -q
```

重新生成文档模板：

```powershell
cd backend
$env:PYTHONPATH = "."
.\.venv\Scripts\python -c "from pathlib import Path; from app.services.rule_packages import load_default_workflow_package; from app.services.rule_package_excel import export_rule_package_excel; Path('../docs/templates/规则包填写模板.xlsx').write_bytes(export_rule_package_excel(load_default_workflow_package().model_dump(mode='json')))"
```

生成后至少检查：

- 八个工作表和固定表头。
- `数据字典` 为隐藏状态。
- 模板原样导入可以通过结构校验。
- 导出后再导入，阶段、节点、路径、条件和期限数量一致。
- 打印或转 PDF 时说明页和数据页没有被横向拆成两页。

## 9. 前端开发约定

- 使用 Vue 3、TypeScript 和组合式 API。
- 页面按业务域放入 `views`，业务组件后续拆分到 `features`。
- 网络请求统一走 `src/api/http.ts`。
- 确认框、密码输入和成功提示统一走 `src/utils/dialogs.ts`，禁止直接使用浏览器原生 `window.confirm`、`window.alert` 或 `window.prompt`。
- 删除操作必须先经过站内确认框；已纳入法律文书的证据由后端返回 `409`，前端保留原记录并展示错误。
- 用户登录状态统一走 `src/stores/auth.ts`。
- 视觉使用 `src/styles/tokens.css` 中的颜色和间距变量。
- 默认保持浅色法律风格，不使用大面积黑色背景。
- 新增按钮时优先使用 Lucide 图标。

## 10. 后端开发约定

- API 路由放在 `app/routes`。
- 数据模型放在 `app/models`。
- 请求和响应放在 `app/schemas`。
- 业务流程放在 `app/services`。
- 所有案件资源必须检查对象级权限。
- 敏感操作写入 `AuditLog`。
- 不在代码中保存真实密钥。
