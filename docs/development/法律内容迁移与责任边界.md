# 法律内容迁移与责任边界

版本：1.0  
更新日期：2026-11-01

## 1. 原则

法律条文、案例、证据规则、期限和文书模板属于专业法律内容，不属于两位开发人员的工作责任。

工程侧负责：

- 数据结构
- 导入脚本
- 版本机制
- 审核状态
- 展示与检索
- 测试和技术校验

法律内容负责人负责：

- 来源真实性
- 现行有效性
- 适用范围
- 条款解释
- 案例真实性
- 文书写法
- 最终发布确认

## 2. 可以先做什么

现有法律内容可以作为初始化草稿导入，但必须标记：

```text
review_status = pending
content_source = imported_draft
```

工程可以先使用这些数据验证：

- 字段结构
- 检索
- 分类
- 页面展示
- 文书填充
- 来源链接

不得把未经复核的数据直接作为正式法律依据对外发布。

## 4. 迁移步骤

1. 从已有法律知识库导出原始数据。
2. 统一字段、编码和 ID。
3. 补充来源和生效日期。
4. 标记为待复核。
5. 法律内容负责人逐条复核。
6. 通过后改为 `approved`。
7. 导入正式演示知识库。
8. 运行检索和文书回归测试。

## 5. 工程验收

工程侧至少保证：

- 来源字段可存储和展示。
- 审核状态不可为空。
- 未审核内容有明确提示。
- 知识库有版本号。
- 更新知识库后向量缓存可重建。
- 文书引用可以回溯到法条 ID。
- 删除或失效内容不会继续被检索。

## 6. 不阻塞工程

法律内容复核可以与工程开发并行。

阶段 1 使用：

- 当前演示规则。
- 待复核法律内容。
- 明确免责声明。

阶段 4 正式部署前，必须完成法律内容复核。

## 7. 对外表述

开发人员和 AI 工具不得自行写“该法条一定适用于用户”，应使用：

- “知识库中的相关法条”
- “请结合现行法律和当地规则”
- “建议人工复核”
- “以下内容仅供参考”

法律内容更新后，应记录版本和更新时间。
