# 分阶段分工与验收

> 本文中的测试数量是各阶段完成时的历史验收记录；当前测试口径以 [部署与恢复](../deployment/部署与恢复.md) 和仓库最新测试结果为准。

版本：2.0
更新日期：2026-11-01

## 1. 执行规则

- 每个阶段只有一条主业务链路。
- 每个阶段先完成契约门槛，再并行开发。
- 每个任务使用任务编号，原则上不超过 1.5 人日。
- 每个阶段设置一名集成负责人，另一人负责对应端的门禁复核。
- 参考工作量用于平衡分工，不作为考勤承诺。
- 法律内容由外部负责人并行提供，开发只负责结构、导入和展示。

### 证据规则边界

- B 负责证据规则模块、规则样例、缺口判断和测试。
- A 负责证据路由、上传、存储、文件权限、数据库和审计。
- B 不直接修改 `routes/evidence.py`、`services/evidence.py`、证据模型或迁移。
- 规则模块只接收结构化输入，返回可解释的判断结果，不直接改变案件状态。
- 页面使用“材料形式异常、完整性不足、真实性存疑提示”等表述，不下真伪鉴定结论。
