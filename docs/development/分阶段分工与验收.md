# 分阶段分工与验收

版本：1.0  
更新日期：2026-11-01

## 原则

- 先完成一条可运行的业务主线。
- 每阶段独立合并、独立验收。
- 当前阶段没有跑通，不开始下一阶段的大规模开发。
- 法律内容由外部负责人并行准备，不阻塞工程基础设施。

---

## 阶段 1：欠薪主链路稳定化

目标：

```text
登录
→ 创建欠薪案件
→ 多轮 AI 咨询
→ 查看案件流程
→ 上传证据
→ 查看证据缺口
→ 生成仲裁申请草稿
→ 管理员分配律师
→ 律师查看案件
```

### 开发 A

1. 冻结 Auth、Case、Consultation、Evidence、Document 接口。已完成。
2. 增加案件工作流节点、允许下一步和前置条件。已完成。
3. AI 回复返回稳定结构化字段。已完成。
4. 证据列表返回稳定缺口结构。已完成。
5. 文书生成返回固定类型和文本。已完成。
6. 补权限、接口和回退测试。已完成。
7. 导出 OpenAPI。已完成。

当前状态：前后端联调已完成，Mock 已替换为真实接口，桌面和移动端端到端测试通过。

新增接口：

```text
GET  /api/v1/cases/{case_id}/workflow
POST /api/v1/cases/{case_id}/transitions
```

### 开发 B

1. 案件工作台展示工作流、当前节点和可选项。
2. AI 对话展示分类、下一步和演示模式。
3. 证据页展示类别、完整性、缺口和错误。
4. 仲裁申请文书预览和 TXT 下载。
5. 管理员分配和律师案件页联调。
6. 使用契约 Mock，不等待后端完成。
7. 补桌面与移动端 Playwright。

### 验收

- 后端测试全部通过。
- 前端测试、类型检查和构建通过。
- Playwright 主链路通过。
- 演示账号可完成整条流程。
- 文书明确标记为草稿。
- 律师无法查看未分配案件。
- API 契约和实现一致。

当前状态：阶段 1 已完成并通过合并前验证。

## 阶段 2：证据与文书增强

目标：把证据处理从规则 Demo 提升到可用试点。

### 开发 A

1. 增加 OCR Provider 接口。
2. 支持 PDF、图片和 DOCX 文本提取。
3. 增加合同文本提取和结构化审查。
4. 增加 DOCX/PDF 文书导出。
5. 文书版本和引用证据目录。
6. 增加材料访问审计。
7. 增加 OCR 和导出失败回退。

### 开发 B

1. 材料 OCR 处理进度和失败状态。
2. 证据合法性、关联性、充分性和形式完整性页面。
3. 合同风险报告和人工复核入口。
4. 文书编辑器、版本切换和下载。
5. 处理长文本和移动端阅读。
6. 补异常状态 E2E。

### 验收

- 图片和 PDF 能提取文本或明确提示失败。
- 证据评估包含可解释依据和缺口。
- 合同报告不宣称真伪鉴定。
- 文书可以导出 DOCX/PDF。
- 文件访问权限和审计有效。

## 阶段 3：服务闭环扩展

目标：覆盖更多纠纷类型和律师协作。

### 开发 A

1. 违法解除、未签合同、加班费、工伤和劳务报酬规则。
2. AI 模拟对话和评分接口。
3. 维权帮助机构数据。
4. 律师意见、服务记录和收益台账接口。
5. 管理员规则、律师和材料接口。
6. 统计和匿名话题接口。

### 开发 B

1. 六类纠纷表单和流程页面。
2. AI 模拟角色、评分和教练点评。
3. 仲裁委和法院入口页面。
4. 本站律师和人工求助。
5. 管理员用户、律师、规则和审计页面。
6. 热门问题和用户历史体验。

### 验收

- 六类纠纷至少有对应规则和证据清单。
- 每个阶段均有申请人工协助入口。
- 律师服务记录可追踪。
- 管理员能够配置律师和分配案件。
- 不公开其他用户原始咨询。

## 阶段 4：生产化

### 开发 A

1. PostgreSQL + Alembic。
2. MinIO 对象存储。
3. Redis/Celery 异步任务。
4. HTTPS、限流、日志、监控和备份。
5. 全量权限、文件和并发测试。
6. Docker 和生产部署验证。

### 开发 B

1. 页面性能、可访问性和移动端完善。
2. 部署后全流程验收。
3. 用户、律师、管理员操作手册。
4. 生产演示脚本和故障提示。
5. 浏览器兼容性测试。

### 验收

- Docker Compose 可启动。
- 数据迁移可重复执行。
- 备份可恢复。
- 敏感材料不公开访问。
- 生产账号和密钥全部更换。
- 法律内容完成来源与时效复核。
