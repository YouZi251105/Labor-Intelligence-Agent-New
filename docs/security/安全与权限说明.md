# 安全与权限说明

版本：0.2.0 Demo
更新日期：2026-11-02

## 1. 当前安全措施

### 身份认证

- 密码使用 Argon2 哈希。
- 登录成功后签发 JWT。
- JWT 默认有效期 24 小时。
- 前端通过 Bearer Token 调用受保护接口。

### 角色

| 角色 | 权限 |
|---|---|
| 劳动者 | 注册、登录、创建自己的案件，提交咨询、材料和文书，维护实名资料 |
| 律师 | 查看管理员分配给自己的案件，提交律师意见、服务记录和收益记录 |
| 管理员 | 管理用户、律师、案件分配、规则、材料、收益和审计记录；只读访问案件业务材料 |

### 对象级权限

- 普通用户只能访问 `owner_id` 为自己的案件。
- 律师只能访问 `assigned_lawyer_id` 为自己的案件。
- 管理员可以访问全部案件。
- 未授权案件统一返回“不存在”，避免泄露案件存在性。
- 案件读取与案件写入使用不同权限检查。被分配的律师和管理员可以读取案件上下文，但不能代替劳动者发送咨询、修改流程、上传证据或生成文书。
- 实名资料、案件创建和劳动者咨询接口只允许 `user` 角色调用。
- 律师和管理员访问劳动者专属接口时返回 `403`；访问未分配案件仍返回 `404`。

### 文件处理

- 限制允许的扩展名。
- 检查基础文件头。
- 限制单文件 20MB。
- 计算 SHA256。
- 同一案件不允许重复文件。
- 文件不通过静态目录公开访问。

### 审计

当前已记录：

- 案件创建。
- AI 咨询。
- 证据上传。
- 合同审查。
- 文书生成。
- 案件分配。
- 密码重置。
- 账号启用、停用和角色权限检查。

## 4. SHA256 的正确理解

SHA256 用于验证文件从上传后是否发生变化。

它不能证明：

- 文件内容真实。
- 文件来源合法。
- 签章或签名真实。
- 材料具有证明力。
- 材料已经获得司法认可。

区块链或可信时间戳可以作为后续增强，但不能把上链宣传成自动判断真假。

## 5. AI 数据边界

### 本地演示

未配置 Key 时，AI 规则在本地运行。

### 千问模型

配置 `QIANWEN_API_KEY` 后，用户咨询内容会发送给第三方模型服务。正式使用前应：

- 取得用户授权。
- 在隐私政策中说明处理目的和范围。
- 尽可能脱敏身份证、电话和住址。
- 明确保存期限。
- 为律师和用户提供撤回授权方式。

## 6. 律师保密

- 律师只查看被分配案件。
- 不得转发案件材料。
- 不得将真实案件内容输入未经批准的第三方工具。
- 正式运营前应签署保密协议并记录材料访问。

## 7. 生产上线检查

1. 更换所有演示账号和密码。
2. 设置随机的 `SECRET_KEY`。
3. 使用 PostgreSQL 和生产级连接池。
4. 使用 MinIO/S3 保存材料。
5. 增加对象存储访问控制。
6. 启用 HTTPS。
7. 使用 `infra/scripts/backup.ps1` 和 `restore.ps1` 执行备份恢复演练。
8. 通过管理员审计接口查询关键操作。
9. 通过请求 ID、`/metrics`、结构化日志和外部告警平台监控服务。
10. 完成隐私政策、用户授权和法律免责声明。
11. 由法律专业人员复核规则和文书模板。
12. 进行越权、文件上传和敏感信息测试。
