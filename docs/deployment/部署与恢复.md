# 部署与恢复

版本：0.2.0  
更新日期：2026-11-02

## 1. 部署组件

`docker-compose.yml` 包含：

- PostgreSQL 16 + pgvector
- Redis 7
- MinIO
- FastAPI 后端
- Celery worker
- Vue 构建产物 + Nginx 前端

默认本地开发仍使用 SQLite、本地文件和同步任务。Compose 环境通过变量切换为 PostgreSQL、MinIO/S3 和 Celery。

## 2. 环境准备

1. 安装 Docker Desktop。
2. 复制环境文件：

```powershell
Copy-Item .env.example .env
```

3. 修改 `.env`：

- `SECRET_KEY`
- `POSTGRES_PASSWORD`
- `MINIO_ACCESS_KEY`
- `MINIO_SECRET_KEY`
- 对外域名和可信主机

不要把 `.env` 提交到 Git。

## 3. 启动

```powershell
docker compose up --build -d
docker compose ps
```

后端容器启动时先执行 `alembic upgrade head`，再启动 Uvicorn。

检查：

```powershell
curl.exe http://localhost:8000/api/v1/health
curl.exe http://localhost:8000/metrics
docker compose logs -f backend worker
```

前端默认地址：

```text
http://localhost:8080
```

## 4. 数据迁移

仅执行迁移：

```powershell
docker compose run --rm backend alembic upgrade head
```

查看当前版本：

```powershell
docker compose run --rm backend alembic current
```

回退一个版本前必须先完成数据库备份。

## 5. 备份

### SQLite

在项目根目录执行：

```powershell
$env:DATABASE_URL = "sqlite+aiosqlite:///./data/demo.db"
.\infra\scripts\backup.ps1 -OutputDirectory backups
```

### PostgreSQL

需要本机安装 `pg_dump`，或将脚本复制到具备 PostgreSQL 客户端的容器：

```powershell
$env:DATABASE_URL = "postgresql+asyncpg://labor:password@localhost:5432/labor_intelligence"
.\infra\scripts\backup.ps1 -OutputDirectory backups
```

备份文件只能写入项目 `backups/` 目录，避免误覆盖其他路径。

## 6. 恢复

```powershell
.\infra\scripts\restore.ps1 -BackupFile .\backups\sqlite-20261102-120000.db
```

或：

```powershell
.\infra\scripts\restore.ps1 -BackupFile .\backups\postgres-20261102-120000.dump
```

SQLite 恢复前会保留 `.before-restore` 安全副本。PostgreSQL 恢复需要本机具备 `pg_restore`。

## 7. HTTPS

生产环境使用：

```text
infra/nginx/https.conf.example
```

把域名和证书路径替换为真实值，并将证书目录挂载到前端 Nginx 容器。不要在仓库中保存私钥。

## 8. 安全与观测

- 所有响应带 `X-Request-ID`。
- 登录和注册接口启用固定窗口限流。
- `/metrics` 输出请求数量、状态码和耗时汇总。
- Nginx HTTPS 示例默认拒绝公网访问 `/metrics`。
- 日志不记录材料正文、密码或身份证号明文。

## 9. 回滚

1. 停止新版本服务。
2. 恢复上一版本镜像或 Git 提交。
3. 使用备份恢复数据库。
4. 启动旧版本并检查健康接口。
5. 记录回滚原因和影响范围。

## 11. 隔离验证栈

验证配置：

```text
infra/validation/docker-compose.yml
```

默认只公开前端 `18080`，PostgreSQL、Redis 和 MinIO 仅位于容器内部网络。

中国大陆网络可使用镜像参数：

```text
VALIDATION_REGISTRY=mirror.ccs.tencentyun.com
PIP_INDEX_URL=https://mirrors.cloud.tencent.com/pypi/simple
NPM_REGISTRY=https://registry.npmmirror.com
```

启动：

```bash
export VALIDATION_PUBLIC_PORT=18080
sudo -E docker compose \
  -f infra/validation/docker-compose.yml \
  -p labor-stage4-validation \
  up -d --build
```

停止并删除测试资源：

```bash
sudo docker compose \
  -f infra/validation/docker-compose.yml \
  -p labor-stage4-validation \
  down --volumes --remove-orphans
```

### 千问 API Key

不要将 Key 写入 Compose、代码或 Git。

服务器验证环境使用项目根目录的 `.env.validation`：

```env
QIANWEN_API_KEY=sk-实际密钥
QIANWEN_MODEL=qwen-plus
```

设置权限：

```bash
chmod 600 .env.validation
```

也可以使用隐藏输入脚本，避免通过编辑器或命令历史暴露 Key：

```bash
bash infra/scripts/configure-qianwen.sh
```

脚本会隐藏 Key 输入、设置文件权限、重建后端，并只输出是否加载成功、是否仍为占位值以及模型名称。

验证 Compose 能读取该文件后，重建后端：

```bash
sudo -E docker compose \
  -f infra/validation/docker-compose.yml \
  -p labor-stage4-validation \
  up -d --force-recreate backend
```

本地开发将同样两个变量写入 `backend/.env` 或项目根 `.env`。如果两处同时存在，项目根 `.env` 后加载并覆盖后端目录配置。

### Linux 容器内备份示例

```bash
sudo docker compose -f infra/validation/docker-compose.yml \
  -p labor-stage4-validation \
  exec -T db pg_dump -U labor_validation -d labor_validation \
  -Fc -f /tmp/labor-validation.dump
```

恢复前应创建临时数据库进行核对，确认后再恢复到目标库。

### 部署目录没有 `.git` 时

如果执行 `git fetch` 提示 `not a git repository`，说明当前目录是复制上传的部署目录，不是 Git 工作区。不要直接覆盖或删除旧目录，改用新目录克隆，并复用原环境变量和 Compose 数据卷：

```bash
OLD=/home/ubuntu/labor-stage4-validation-20261102-0115
NEW=/home/ubuntu/labor-stage4-validation-main

test -s "$OLD/.env.validation"
git clone --branch main --single-branch \
  https://github.com/YouZi251105/Labor-Intelligence-Agent-New.git \
  "$NEW"
install -m 600 "$OLD/.env.validation" "$NEW/.env.validation"
```

如果新目录已经存在，改为拉取：

```bash
git -C "$NEW" fetch origin
git -C "$NEW" checkout main
git -C "$NEW" pull --ff-only origin main
install -m 600 "$OLD/.env.validation" "$NEW/.env.validation"
```

使用同一个 Compose 项目名启动，数据库、Redis 和 MinIO 数据卷不会丢失：

```bash
cd "$NEW"
export VALIDATION_PUBLIC_PORT=18080
sudo -E docker compose \
  -f infra/validation/docker-compose.yml \
  -p labor-stage4-validation \
  up -d --build
```
